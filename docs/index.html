01 · The hardware

Six buttons, two dialects of HID

Every key was characterized on the bench from raw Bluedroid DATA_IND reports. The photo key speaks keyboard (Enter, for Android camera apps) and echoes consumer volume-up (the iOS shutter convention) — the firmware suppresses the echo so one press means one event. Click a button:

02 · The finding

Invisible to every BLE proxy in the house

1

Scan the mesh

Bermuda's dump_devices saw 357 BLE devices across the ESPHome proxy fleet — including an iTAG three metres from this remote. The remote itself: zero advertisements, even blinking in pairing mode.

2

Dual-radio test

A desktop dual-mode adapter scanning LE and BR/EDR simultaneously heard the same silence on LE. Meanwhile a phone's Bluetooth settings listed it happily — in the Classic section.

3

Verdict

It's Bluetooth Classic (BR/EDR). ESPHome's bluetooth_proxy forwards BLE advertisements only, so no BLE-based tracker can ever see this device. Not a bug — physics and protocol.

If you can't track it, repurpose it: an original ESP32 — the only variant with a BR/EDR radio — becomes the HID host it always wanted.

03 · The build

One component owns the whole stack

Radio

BR/EDR-only Bluedroid

No BLE components on the node, BLE host compiled out, controller in Classic-only mode. The component initializes GAP + esp_hidh itself — nothing to fight ESPHome over.

Pairing

Blink & bond

Unbonded, it loops GAP discovery filtered by HID Class-of-Device. Long-press the remote until it blinks — found, connected, bonded. SSP confirm is pinned to that exact device; unsolicited pairing is rejected.

Sleep cycle

Wakes itself back in

The remote sleeps aggressively. On press it re-pages the host (~2 s), and a 60 s retry pages it back as belt-and-braces. The wake press itself is consumed by reconnection — a characterization trap.

04 · Field notes

Traps, documented

The wake press never delivers. It spends itself re-opening the HID session, so any "press each button in order" characterization starts off-by-one. Anchor from the end of the sequence, or wake it with a throwaway press first.
take_photo double-transmits. Keyboard 0x28 plus consumer 0x08 (vol+) per press — shutter compatibility for both phone platforms. Suppressed in firmware within 500 ms of keyboard activity; standalone volume presses pass through.
CP2102 + esphome logs = reset loop. The log client's DTR/RTS handling holds the board in reset; the "log" is an endless newline flood. Read the console with a raw serial reader that parks both handshake lines.
